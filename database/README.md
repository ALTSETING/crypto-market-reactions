# Website MVP database layer

This directory contains a standalone SQL migration for the future Crypto Market Reaction Database website. It deliberately coexists with the legacy Alembic research schema: the website `events` table is derived from `data/website/events_mvp.parquet` and does not replace old research tables.

## Files

- `migrations/001_create_events.sql` — table, constraints, generated full-text document and indexes.
- `migrations/003_allow_empty_related_assets.sql` — permits crypto-relevant events without evidence for a supported asset.
- `migrations/005_close_public_events_access.sql` — removes browser-role access
  after the Next.js server has a working secret/service-role credential.
- `checks/verify_events.sql` — post-import counts, coverage checks and example queries.
- `../scripts/database/import_events.py` — schema validation, slug preparation and idempotent COPY/upsert.

## Local validation without PostgreSQL

`migrations/004_add_average_reactions.sql` adds the generated columns
`btc_average_reaction`, `eth_average_reaction`, and `sol_average_reaction`.
Each is the sum of the available 1m, 5m, 15m, 1h, 4h and 24h percentage
returns divided by their non-NULL count. Zero participates in the sum and the
count; fewer than three available values produces NULL. One partial B-tree
index per generated average supports these new sort keys. The existing horizon
columns are intentionally not multiplied into 18 extra indexes.

```powershell
python -m scripts.database.import_events --dry-run
python -m pytest -q tests/test_import_events.py
```

## Apply to PostgreSQL or Supabase

Use a direct/session PostgreSQL connection string with SSL where required. Do not commit the real value.

```powershell
Copy-Item .env.example .env
# Set DATABASE_URL in .env.

psql $env:DATABASE_URL -v ON_ERROR_STOP=1 -f database/migrations/001_create_events.sql
python -m scripts.database.import_events
psql $env:DATABASE_URL -v ON_ERROR_STOP=1 -f database/checks/verify_events.sql
```

The importer also accepts the legacy SQLAlchemy prefix `postgresql+psycopg2://` and normalizes it internally. `psql` itself normally expects `postgresql://`.

The migration is intentionally not applied automatically by the importer. This keeps schema changes explicit and gives Supabase operators a chance to review SQL before execution.

For a controlled reclassification of an existing 7,878-row table:

```powershell
python -m scripts.database.import_events --dry-run --classification-only
python -m scripts.database.apply_sql_migration database/migrations/003_allow_empty_related_assets.sql
python -m scripts.database.import_events --classification-only
```

The classification-only mode requires an exact event-ID/slug count match and
updates only `primary_asset`, `related_assets`, and `updated_at`. A repeat run
reports zero changed rows.

## Idempotency

Import uses:

1. a transaction-scoped temporary staging table;
2. `COPY ... FROM STDIN` in batches of 1,000 rows;
3. `INSERT ... ON CONFLICT (event_id) DO UPDATE`;
4. preservation of the original `created_at` and refresh of `updated_at`.

A second import updates the same 7,878 events and cannot create another set of rows.

## Indexes

- Primary-key B-tree on `event_id`: stable upsert and event lookup.
- Unique B-tree on `slug`: SEO page lookup and collision prevention.
- B-tree on `published_at DESC`: date filtering and latest-event pages.
- B-tree on `source`: source filters.
- Partial B-tree on non-NULL `primary_asset`: primary-asset filters without indexing 87 ambiguous rows.
- B-tree on `category`: category filters.
- GIN on `related_assets`: `@>`/overlap asset filters.
- GIN on generated `search_vector`: full-text title/source/category search.

No indexes are added to individual reaction columns in the MVP because search and export do not filter by them yet.

`related_assets` contains only explicitly evidenced supported assets. Its array
may be empty for a general crypto event; an empty array is distinct from SQL
NULL and remains covered by the same GIN index.

## Full-text search

`search_vector` is generated by PostgreSQL. Title tokens receive weight A; source and category receive weight B.

```sql
SELECT event_id, slug, title, published_at,
       ts_rank(search_vector, websearch_to_tsquery('english', 'ethereum ETF')) AS rank
FROM public.events
WHERE search_vector @@ websearch_to_tsquery('english', 'ethereum ETF')
ORDER BY rank DESC, published_at DESC;
```

The same query shape supports `sec ethereum`, `binance hack` and `blackrock bitcoin` without embeddings.

## CSV export architecture

Reaction fields remain ordinary columns, so a future backend can apply exactly the same search/filter query and stream selected rows as CSV. A database-side diagnostic export can use:

```sql
\copy (
  SELECT event_id, slug, title, published_at, source, source_url,
         primary_asset, related_assets, btc_1h, eth_1h, sol_1h
  FROM public.events
  WHERE search_vector @@ websearch_to_tsquery('english', 'ethereum ETF')
  ORDER BY published_at DESC
) TO 'events_export.csv' WITH (FORMAT CSV, HEADER true)
```

## Supabase read-only security

After import and verification, apply the dedicated RLS migration. Keep imports
on a server-only database-owner/service-role connection.

```powershell
psql "$env:DATABASE_URL" -v ON_ERROR_STOP=1 -f database/migrations/002_enable_events_readonly_rls.sql
```

The effective SQL is:

```sql
ALTER TABLE public.events ENABLE ROW LEVEL SECURITY;

REVOKE ALL PRIVILEGES ON public.events FROM PUBLIC, anon, authenticated;

GRANT USAGE ON SCHEMA public TO anon;
GRANT SELECT ON public.events TO anon;

CREATE POLICY events_public_read_only
ON public.events
FOR SELECT
TO anon
USING (true);
```

No public write policy is created. The `authenticated` role receives no table
privileges until the product has an explicit authenticated access design.
Never expose `DATABASE_URL`, a database password, or the Supabase service-role
key in browser code.

The public-read migration above documents the earlier MVP state. The protected
server-only architecture must finish with `005_close_public_events_access.sql`:

```powershell
python -m scripts.database.apply_sql_migration database/migrations/005_close_public_events_access.sql
```

Apply migration 005 only after `SUPABASE_SECRET_KEY` is configured and Search,
event pages, and sitemap have passed using that credential. It keeps RLS
enabled, drops all anon read policies, revokes every table privilege from
`anon` and `authenticated`, and preserves SELECT for `service_role`.
